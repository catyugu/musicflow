# 曲谱同步自动化工具链：需求与实施计划（修订版）

## 一、已确定的需求

**目标：** 开发一套无 GUI、CLI-first、适合 Agent 操作的工具链，以原始 PDF 乐谱、真实演奏音频和符号乐谱为输入，自动制作曲谱同步视频（MP4）。同时支持固定谱行切换与单列连续流动两种显示模式。

### 输入材料与支持范围

**原始 PDF 乐谱、音频，以及至少一种符号乐谱是必需的。** 符号乐谱可以是 MusicXML（`.musicxml`、`.xml`、`.mxml`）、压缩 MusicXML/MXL（`.mxl`）或 MIDI（`.mid`、`.midi`）。

| 场景 | 输入材料 | 固定谱行切换 | 单列连续流动 |
| --- | --- | --- | --- |
| A. 自己创作的作品 | PDF + 音频 + MusicXML/MXL | 支持 | 支持 |
| B. 已有数字乐谱资料 | PDF + 音频 + MusicXML/MXL | 支持 | 支持 |
| C. 只有 MIDI 辅助数据 | PDF + 音频 + MIDI | 支持 | 暂不支持 |

这里对流动模式作出明确限定：**MIDI 不含完整的记谱排版语义，不能保证重建与原谱一致的谱号、声部、连梁、力度和演奏记号。** 因此 MIDI-only 仍可用于 PDF 原谱切换与音频对齐，但不作为原生连续流动模式的充分输入。通过 MIDI 转写 MusicXML 不自动视为等价输入；必须先核对并修订符号谱。

### 功能要求

- **固定谱行切换（`switch`）**：始终呈现原始 PDF 的谱面，不重新排版；检测谱行、裁切、缩放与 Padding，并按演奏进度切换谱行。
- **单列连续流动（`flow`）**：参照 [score-sync-video](https://github.com/tofucurd/score-sync-video) 的基本观看方式，将当前多声部谱表组合纵向排列为一个连续系统，谱面随演奏**横向平滑移动**，屏幕中的竖直阅读线固定；不是整页 PDF 纵向滚动，也不是定时切换截图。
- **原谱保真边界**：`switch` 的画面严格来自 PDF；`flow` 从 MusicXML/MXL 重新排版，PDF 是谱源校勘依据，不能声称复现 PDF 的原始版面。遇到两者谱号、音符、节奏、声部、反复、演奏记号等实质差异，须输出诊断并修正或标记未确认，不得静默忽略。
- **音频对齐**：利用符号事件对真实演奏录音建立时间映射，处理速度变化、反复、跳跃及局部对齐误差。流动模式需要达到音符/拍位所需的连续横坐标精度，不能只靠谱行开始时间。
- **时间基准**：原音频始终是主时钟；为生成滚动动画而平滑摄像机位置，不得改变音乐事件时间、变速音频或假定录音为恒定 BPM。
- **视觉扩展**：小节/音符高亮、双层曲式进度条、唱词/导赏等暂不列入必需验收。基本流动模式至少具有固定阅读线、平滑滚动、可辨识的完整谱表及正确的同步关系。
- **无 GUI**：所有操作经 CLI、配置文件、诊断图片和结构化修正文件完成；使用无窗口的渲染组件不等于引入交互 GUI。
- **可复现**：支持批处理、增量重跑、缓存、自动诊断与 Agent 修正；保存输入指纹及必要的人工校勘/对齐证据。
- **运行环境**：Windows 原生、CPU 可运行，不使用 Docker；MP4 为交付格式。

## 二、实现路径

```text
PDF（必需）       MusicXML/MXL 或 MIDI（至少一种）       Audio（必需）
    │                         │                         │
    ├─ 谱行检测/原谱裁切      ├─ 符号事件与演奏路线解析 │
    │                         │                         │
    └─────────────┬───────────┴──────────────┬──────────┘
                  │                          │
           PDF/符号谱校核               符号谱与真实录音对齐
                  │                          │
                  └──────────┬───────────────┘
                             │
                 统一演奏时间轴、诊断与修正
                             │
                   ┌─────────┴──────────┐
                   │                    │
            switch（全部合法输入）    flow（须 MusicXML/MXL）
                   │                    │
            PDF 谱行切换渲染        Verovio 连续 SVG 排谱
                   │                    │
                   │              事件到 SVG 横坐标映射
                   │                    │
                   │              固定阅读线 / 平滑滚动
                   └─────────┬──────────┘
                             │
                      FFmpeg + 原音频
                             │
                            MP4
```

### 共享数据与对齐

1. 解析 MusicXML/MXL 或 MIDI，获得谱位、时值、音高、声部、源小节及事件身份；根据实际录音确定反复、跳转的**演奏路线**。同一小节的不同演奏次数必须有不同的 occurrence 身份。
2. 对齐音频并保存 `score_position → audio_time` 映射、置信度及必要的经审核时间锚点。既有 PDF 谱行映射与新增流动模式共享这条演奏时间轴。
3. `switch` 为各谱行绑定源谱位区间，按原始 PDF 中的几何区域切换。
4. `flow` 为每个可见符号事件建立 `source_event_id / occurrence → SVG x` 映射，结合对齐结果得到以音频时间为自变量的滚动位移。布局时间、事件时间和摄像机位移分离，避免动画缓动破坏音画同步。
5. 校勘或对齐失败时，生成局部诊断图、时间偏差报告、待确认项目和可追踪的修正文件；不静默产生“成功”结果。

### 候选技术栈

| 模块 | 工具 | 说明 |
| --- | --- | --- |
| 工作流与 CLI | Python + uv | 同一 CLI 管理两种显示模式与缓存 |
| 符号乐谱解析 | Partitura | MusicXML/MXL/MIDI 读入，建立统一事件时间轴 |
| PDF 处理 | PyMuPDF + Pillow | 原始谱行检测、裁切、固定模式渲染及校勘 |
| 原生连续谱面 | Verovio | 仅供 `flow` 使用；将 MusicXML/MXL 排版为可定位的 SVG |
| 音频对齐 | Parangonar / SyncToolbox | 候选工具，仍需真实录音验证 |
| 帧合成与视频封装 | SVG 光栅化组件 / Pillow + FFmpeg | CPU 分块合成、固定阅读线、MP4 封装 |

提示：不应该要求用户本地系统级/用户级安装 `Verovio`，应该引导用户在项目局域临时拉取和构建。

## 三、阶段性验证用例

| 阶段 | 验证输入 | 验收目标 |
| --- | --- | --- |
| **V1：谱面处理** | 多页 PDF；至少一个 MusicXML/MXL 样例 | PDF 原谱谱行检测、裁切、Padding 不截断；Verovio 生成可定位的单列 SVG，多谱表及谱面完整性可核查 |
| **V2：符号信息与音频对齐** | PDF + 音频 + MusicXML/MXL；另以 MIDI 单独提供符号信息 | 两类符号输入均能独立驱动 `switch` 的谱行定位、音频对齐和 MP4 输出；覆盖同源合成音频、独立演奏录音、变速及反复 |
| **V3：单列连续流动** | PDF + 音频 + MusicXML/MXL | 生成横向连续流动视频：固定阅读线、拍位/音符级滚动位置、变速与重复段正确、无切谱跳屏；检查原谱校勘、短时预览、分块边界和音画同步 |
| **V4：自动化回归** | V1–V3 的全部合法样例及非法输入 | Windows 原生 CPU、CLI 端到端、可复现、可增量重跑；`PDF + 音频` 缺符号文件明确拒绝；仅 MIDI 的 `flow` 明确拒绝；缓存重用及续渲结果一致 |
